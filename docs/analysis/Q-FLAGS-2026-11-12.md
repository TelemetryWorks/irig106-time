# Q-FLAGS — owner refinement, 2026-11-12

Owner decision: **refine**. The stamp's source controls whether the reserved
secondary format prevents decoding. This documentation records the accepted
behaviour; the existing Rust implementation has not yet been changed.

## Verbatim basis and visual page checks

106-24R1 §11.2.1.1 g, printed **11-8/11-9** (chapter PDF **16/17**):

> Bit 6: Indicates the IPTS time source.
>
> 0 = Packet header 48-bit RTC.
>
> 1 = Packet secondary header time (bit 7 must be 1).
>
> Bits 3-2: Indicate the packet secondary header time format.
>
> 11 = Reserved

§11.2.1.3 b, printed **11-11** (PDF **19**), says:

> 48-bit RTC format (plus 16 high-order zero bits)

The RTC quotation is on 11-11, not 11-8/11-9. The owner selects the severity
and value-retention rules below; the standard supplies the bit meanings,
not the library's finding identifiers or error API.

In 106-05..15 the equivalent sections are **10.6.1.1 g** and **10.6.1.3 b**.
106-05..11 use the expanded phrase:

> 48-bit Relative Time Counter format (plus 16 high-order zero bits)

and describe the alternative as “64-bit absolute format”. 106-13 onward use
“48-bit RTC format” and “64-bit format”. These editorial differences do not
change the bit-6 RTC selection. The older reserved 01/10 meanings remain
edition-specific; this decision addresses 11 and does not infer an edition.

## Accepted rule and planned fixtures

Trace: **L1-IPT-007 → L2-IPT-107 → L3-IPT-107**. L3-ENC-103's
cross-reference is qualified to avoid reinstating a blanket RTC rejection.

| Condition | Stamp answer | Finding |
|---|---|---|
| source=1, presence=0 | No time | Error, TF-015; retain other flag evidence. |
| source=1, format=11 | No time | Undefined-format error; report missing header too if applicable. |
| source=0, format=11 | Read padded 48-bit RTC normally | TF-005 warning, RTC value kept. |
| source=0, format=11, presence=1 | Same RTC answer | Also report the secondary header time itself as unreadable; its error does not discard the RTC stamp. |

For the modern baseline, the stamp rejection predicate is
`source == 1 && (presence == 0 || format == 3)`. All other flag bits retain
their independent meanings and findings. Errors apply to the affected time;
a warning does not remove a valid value. Reserved RTC padding is reported
separately and is never reinterpreted as counter bits (L3-RTC-102).

| Literal flag | Required stamp result |
|---|---|
| `0x0C` | RTC with TF-005 warning. |
| `0x8C` | RTC with TF-005; separately unreadable secondary time. |
| `0x4C` | No stamp, errors: missing required header and undefined format. |
| `0xCC` | No stamp, undefined-format error. |
| `0x40` | No stamp, missing-required-header error. |

The planned exhaustive modern-baseline fixture covers all **256** flag bytes:
128 source=0 RTC cases, 48 source=1/presence=1/defined-format cases and 80
rejected cases. These are hand-derived dispatch counts, not executed tests
or claims that unrelated flag findings disappear. Relative to the blanket
format=11 rejection, 32 RTC cases become readable.

## Implementation boundary

After the documentation PR merges, a **separate code PR** will begin with a
tests-only commit demonstrating the failing RTC/reserved-format cases on
main, then implement the refinement. It will include exhaustive flags and
the literal fixtures above, `/// Requirements:` markers for the complete
007/107/107 lineage, correct code `Traces` tags, regenerated trace matrix,
CHANGELOG behaviour note and the full CI equivalent. Existing correct error
cases are regression checks, not falsely claimed as individually failing
baseline tests. No Rust source or test changes are part of this docs update.

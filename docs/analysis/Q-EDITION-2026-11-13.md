# Q-EDITION — accepted caller declaration policy

Owner decision **2026-11-13**. Trace:
**L1-EDN-002 → L2-EDN-201 → L3-EDN-201**. This selects packet layout;
it does not rewrite raw TMATS or setup-record metadata.

## Sources and boundary

| Source | Evidence |
|---|---|
| 106-04 §10.6.3.3 Figure 10-15, printed 10-31 / full PDF 289 | `RESERVED`, `DATE`, `FMT`, `EXT`: external-present bit 0, reserved bits 3–1; FMT 6–15 reserved. |
| 106-05 Figure 10-16a, printed 10-37 / chapter PDF 41 | SRC layout and FMT 0xF NONE begin here. |
| 106-24R1 §11.2.1.1 e, printed 11-6 / PDF 14 | Header data-type version is “a value at or below the release version of the standard applied to the data types”. Thus 0x01 alone does not select EXT. |
| 106-04 §10.6.7.2.2/Figure 10-34, printed 10-48 / full PDF 306 | No setup version field exists. |
| 106-05 Figure 10-34b, printed 10-55 / PDF 59 | “Reserved. (Bits 31-0) are reserved.” No setup version code. |
| 106-07 Figure 10-50, printed 10-72 / PDF 76 | CH10VER appears, with only 0x07 assigned. It cannot supply missing 106-04/05 evidence. |
| 106-04 Table 9-1, printed 9-8 / full PDF 186 | G\106: “VERSION OF IRIG 106 STANDARD USED TO GENERATE THIS TMATS FILE”. This dates TMATS, not automatically packet layout. |

These archive/page references retain the already documented T-6 and EDN
boundary checks. The owner supplies the adoption policy; the standard does
not specify this reader's evidence-resolution API.

Basis vocabulary is taken from **TelemetryWorks/irig106-tmats**,
`docs/adr/0028-edition-declarations-and-validation-basis.md`, commit
`41030d54dfbd8a539c2810d023dd0670bfd3dc1f`:
[pinned ADR-0028](https://github.com/TelemetryWorks/irig106-tmats/blob/41030d54dfbd8a539c2810d023dd0670bfd3dc1f/docs/adr/0028-edition-declarations-and-validation-basis.md).
The ADR names **override**, **declared**, and **fallback**. It also preserves
TMATS and recording-format declarations separately: differing declarations
are not automatically a conflict. This task adopts that vocabulary, not
TMATS's validation fallback algorithm for selecting EXT packet layout.

## Accepted resolution and planned fixtures

| Evidence | Packet-layout result and basis |
|---|---|
| Explicit caller declaration/override = 106-04 | EXT; **override**. |
| Explicit caller declaration/override = 106-05 | SRC; **override**. |
| G\106=04, caller explicitly opts into its use as packet edition | EXT; **declared, assumed from TMATS**. Record raw declaration and policy opt-in. |
| G\106 without that opt-in, or header 0x01 alone | Unresolved; raw bits retained; no invented SRC/None labels. |
| Conflicting adopted packet-layout evidence | Unresolved plus finding, even with an override. Do not silently suppress contradictory adopted evidence. |
| No usable evidence | Unresolved; **fallback** vocabulary cannot authorize guessed EXT. |

A different *unadopted* TMATS-file edition is metadata, not automatically
contradictory packet-layout evidence. Likewise a lower data-type-version
hint is allowed by “at or below”; it is not proof of the recording's edition.
Keep later valid setup evidence distinct and applicable only where defined.

Planned fixtures cover every row, missing/malformed G\106, conflicting
explicit override versus opted-in TMATS, raw nibble 3 with no None label,
106-04/05 reserved CSDWs and later CH10VER 0x07. Existing shared-type mapping
constructors decode code lists; they do not implement this resolver.
No code or tests change in this documentation PR.
